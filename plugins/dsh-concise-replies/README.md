# 精炼结果回复

为 DSH 提供面向普通用户的执行进展和结果回复。长任务开始时简要交代先处理什么，再按关键发现、实际变化、核对结果和阻碍更新。单项结果用短段落，多个独立结果用无序列表。保留实际缺口、必要操作以及用户要求的完整交付内容。

## 输入框中的下一步建议（1.2.0）

当前会话的最新一轮结束后，空输入框会显示 AI 根据本轮实际结果生成的一句任务建议，右侧用普通小字提示“Tab 采用”。按 Tab 只将建议填入可编辑草稿，不自动发送；原生撤销和草稿保存继续生效。直接输入自己的内容会隐藏建议，Shift+Tab 保留原来的焦点移动，中文输入法组词时不采用建议。Escape 可忽略本轮建议，已采用或忽略的建议不会因同一客户端切换会话再次弹出。

已有文字、引用、附件、命令、排队消息或正在提交/运行时不展示建议；新任务开始就撤掉旧建议。建议绑定会话 ID 与结束事件序号，异步返回不能覆盖新会话、新一轮或用户草稿。建议仅限最新一轮，不跟随历史阅读锚点切换。原生候选菜单打开时保留菜单的 Tab 操作。

`next-task.js` 通过已有鉴权 Fetch 通道提供建议接口，使用会话原有模型与账号发起一次无工具的简短请求，只传本轮用户原话、公开回复和实际结束原因，不传系统提示、内部推理或运行环境指令。同一 Host 内按会话与结束事件复用结果、合并并发请求，缓存上限 64 项，25 秒超时；新任务开始、会话释放或卸载插件会取消未结束的请求。此功能会产生少量额外模型用量；没有合适下一步、鉴权失败、模型不可用或返回无效时保留原提示文字，不影响任务、总结和草稿。缓存不跨 Host 重启保留。

建议使用用户对 AI 发指令的口吻。失败、部分完成、停止和中断时优先核对真实结果或补齐明确缺口，不能假定操作成功或已撤销，也不盲目重复有副作用的操作。建议不是执行结果或自动执行指令，采用后仍由用户决定是否发送。

界面使用原生 Slot、独立 React Portal 与带草稿版本校验的 `inputActions.insertText()`；不替换 React 管理的原提示节点或编辑器内容。

验收（2026-11-16）：复用已有桌面 Host，通过无头 Chromium 的真实 DSH 客户端验证付款未验证与订单文件缺失两类任务后的模型建议。Tab 填入、不自动发送、保留焦点、继续编辑、撤销、已有草稿保护、Shift+Tab、输入法事件保护、命令菜单 Tab 优先，以及 640px 窄窗口显示均已通过。原生命令会产生不可编辑的命令节点，测试清理使用全选与删除，不通过修改 React/Lexical 子树删除。Host 契约回归覆盖并发去重、新任务取消旧请求、过期请求拒绝、模型失败回退和卸载清理；未启动或重启原有服务。

通过 `systemPrompt.section()` 追加规则，在每次组装模型请求时读取 `reply-policy.txt`。规则影响后续回复，历史回复和会话数据按原样保存。

## 执行过程

执行记录用普通文字表示查找资料、修改文件、处理文档等操作。进行中、停止和遇到问题的步骤仅用文字颜色和简短状态区分。工具命令、参数、原始输出和内部推理都隐藏在日常对话视图之外。具体工作和实际结果由模型发布的简短进展说明。需要用户确认或作答时仍使用 DSH 原有交互。

## 配套原生显示设置

桌面端可用以下 `ui-chat` 设置展开展示运行步骤，并在正常完成后收起过程。

- `transcriptView: detailed`：运行时展开操作摘要和进展。
- `collapseTiming: completion`：正常完成后立即收起过程。
- `foldedReplies: final`：收起时只保留最后的结果回复。

展开已收起的过程时，仍显示同样的操作摘要。用户明确要求的语言、格式和完整交付内容优先。

## 异常结束

模型被停止或请求出错时，往往没有机会生成最后回复。`client.js` 使用原生 `conversation.chat.turnTail` 扩展点，根据持久化 `turn/end.reason.kind` 追加一段普通文字：停止、中断、出错、达到上限、受阻分别说明未正常结束和结果尚未确认。它不把最后一条进展当作总结，不推断已完成的数量，也不声称之前的操作已撤销。未知的异常原因同样保守显示结果未确认。正常完成及分支切换不追加这段兜底文字，不改写已有模型回复或会话历史。

回复规则要求异常任务先说整体实际结果：全未达成说明“没能……”和原因；部分达成先说“只完成了一部分”，再说清已做成与未做成的事。模型正常结束一轮（原生 `completed`）不等于用户要求的每件事都成功；业务结果仍以最终回复及实际产物核对，不能从这个运行状态推断业务完成。

## 验收（2026-11-16）

使用现有桌面服务和真实 DeepSeek 会话，验证运行时进展可见、正常完成后仅保留最终答复、键盘展开能找回原过程并再次收起。普通检查样本最终为 87 字的一段话，保留“付款尚未验证”的缺口；明确要求完整清单时保留全部三项，找不到文件时明确无法判断交付结果。请求历史中确认回复规则已进入模型实际系统提示。

这是模型生成规则与原生显示设置的组合，不使用二次模型改写，也不通过截断正文制造精炼效果。特殊角色的完整系统提示仍由原有角色控制，用户明确要求的完整交付优先。

### 异常结果回归（2026-11-16，1.1.0）

- 真实读取不存在的订单文件：最终明确无法计算总金额，没有输出虚构金额。
- 真实写入第一份测试文件，再读取缺失来源：最终先说“只完成了一部分”；磁盘确认第一份文件存在、第二份结果文件不存在。
- 真实运行中点击原生停止：持久化结束原因为 `aborted`，第二份文件未创建，原生状态为“已停止”；兜底总结显示结果未确认。
- `error`、`interrupted`、`max-tokens`、`blocked` 及未知异常的组件契约回归通过；正常完成和分支切换不追加兜底，注销可清理本插件语言注册。意外中断采用结束事件契约验证，没有通过重启用户 Host 制造崩溃。

验收边界：真实流程覆盖任务失败、部分完成与主动停止；意外崩溃恢复的端到端场景未通过杀进程实测。文字规则能约束模型表达，不能取代对未来每次业务结果的事实验证。异常结束的固定兜底不依赖模型是否遵守规则。
