# 消息阅读锚点

`@local/dsh-running-prompt-status` 将原生用户消息气泡本身改成任务标题：全宽、左对齐，滚动时依次置顶。没有额外复制或渲染的标题文字，也不再在输入框上方或内容区外增加标题栏。

- 每轮用户消息仍保留原来的内容节点与复制按钮；去掉气泡背景和圆角，长文字在标题中省略，悬停查看全文。没有用缩略导航文本代替用户消息。
- 标题是原消息在原来的消息流位置吸顶；滚到下一轮，由下一条原消息接替置顶。历史任务的状态和用时属于该轮本身。
- AI 回复保留原来的内容宽度。只有用户消息铺满滚动内容区，不把整个回复区拉宽。
- 最后一轮内容很短时，仅补足必要的末尾滚动空间，保证最后一条原消息也能滚到顶部。
- 使用原生 Slot 管理生命周期，只对原消息的外层加样式和本插件数据属性，不移动、替换或重建 React 管理的消息子树；状态和用时通过独立 Portal 放进原消息行。
- 卸载时清除本插件的标记、末尾留白和状态节点，恢复原生消息。不要同时启用旧的固定标题插件。

## 阶段与视觉约束

状态读取 `useChat().timeline.turns` 的真实 `turn/end` 原因，以及会话的 `pendingInteraction.kind`；不能用 `running=false` 推断成功，也不能把工具某一次失败当成整轮失败。

| 来源 | 显示 | 视觉 |
| --- | --- | --- |
| 已接收、尚未开始 | 准备中 | 蓝色圆点 |
| 运行中（含工具运行） | 进行中 | 蓝色圆点 |
| approval / question / plan-review | 待审批 / 待回复 / 待确认 | 琥珀色圆点 |
| 用户点击原生停止，任务仍在运行 | 正在停止 | 琥珀色圆点；等待真实结束 |
| 会话结束信号已到、轮次结果尚未到达 | 收尾中 | 灰色圆点；保持最后用时 |
| completed | 已完成 | 绿色圆点 |
| aborted / interrupted | 已停止 / 已中断 | 灰色 / 琥珀色圆点 |
| error / max-tokens / blocked | 失败 / 达到上限 / 受阻 | 红色 / 琥珀色圆点 |
| forked / 不认识的结束原因 / 缺失证据 | 已结束 / 已结束 / 状态未知 | 灰色圆点 |

运行阶段统一显示“进行中”，不因工具执行切换为另一种状态。状态使用简洁的行内小圆点、文字和用时，不使用边框、底色、圆角或标签内边距。圆点统一为 6px 实心圆，用颜色区分状态；旁边保留状态文字，不只依赖颜色。圆点保持静态，不加旋转、呼吸等动效。读屏只播报状态切换，不逐秒播报用时。

用时以 DSH 原生实时钟和轮次真实开始、结束时间为准；等待期间沿用 DSH 原生用时口径，停止、失败和完成后冻结。不会用页面首次观测时间伪造计时起点。停止意图仅观察原生停止按钮；键盘或其他客户端取消以真实结束事件为准。

## 验收边界（2026-11-14）

- 已在真实 DSH 会话验收准备、运行、工具执行、停止请求、已停止、等待回复和答复后的完成；滚动到历史停止轮次时保留停止结果。
- 待审批、待确认、失败、中断、达到上限等边界使用与 DSH 公开契约一致的模拟状态验收，不通过破坏账号或服务制造失败。
- 无头浏览器覆盖窄屏、深浅主题、文字对比度、减少动态效果、强制颜色，以及卸载后的 Portal 和样式清理。状态预览图使用模拟数据，真实会话截图另行保存。

## 原消息标题验收（2026-11-17，1.4.0）

通过现有桌面 Host 和无头真实 DSH 客户端验证：用户原消息节点在滚动前后保持相同身份，每轮只有一份消息内容，独立标题栏和输入框上方标题均不存在。滚动切换历史任务及回到底部时，原消息依次吸顶，状态与用时保留对应轮次；保留原生复制按钮、完整消息内容和长标题悬停文本。检查全宽左对齐、窄窗口和卸载清理，不重启或关闭用户已有服务。

## 标题宽度约束（1.4.2）

每轮用户消息标题容器与消息正文列等宽、左右边缘对齐，宽度取原生 `[data-chat-flow]` 的 `clientWidth`；既不使用整个滚动视口宽度，也不额外减去 32px。文字容器通过 `flex: 1` 占满扣除复制、状态、用时后的剩余空间，长文本仅在实际边界处省略，保留完整原文。窗口变化时由现有 ResizeObserver 同步更新。

## 重复运行提示（1.4.3）

隐藏输入框上方原生“深度求索中、用时……”整行提示及其装饰样式，任务状态与用时仍在用户消息标题中显示。原生节点保留在 DOM，继续作为实时用时的数据来源，不改动运行、停止及工具记录。

## 用时与正文之间的分割线（1.4.4）

移除原生 `button[data-turn-process]` 下边框，不显示“已完成，用时……”与正文之间的横线；保留用时文字、原有间距和展开过程功能。

## 发送时的首帧定位（1.5.0）

新消息的原生本地发送预览（transcript echo）与正式用户消息采用相同的标题样式、正文列宽度和定位。新增/替换消息时立即处理 DOM，并在布局阶段及原生尺寸重算后补齐末尾空间、定位到顶部；首次可见之前确认位置已对齐，取消原先“下一帧处理、再下一帧滚动”的延迟链。定位过程不使用平滑滚动，也不复制或重写消息文本。

只有最新消息节点发生变化才启动定位，加载旧历史不会把位置拉回最新消息；首帧校准期间的滚轮或触摸操作优先，卸载时清理待执行的帧回调和临时可见性标记。待发送预览仅显示“准备中”，不会借用上一轮的状态或用时。排队与补充当前任务的 steering 不冒充新一轮任务标题。

无头真实 DSH 客户端验收覆盖空白会话首条发送、连续发送（含 Enter）、回看历史后发送；原生临时预览和正式消息的 23 个可见帧均在顶部既有 8px 间距处，零位置异常、零页面脚本错误。同步确认标题仍与正文同宽、用时与正文之间的分割线仍隐藏。

## 消息显示稳定性（1.5.1）

末尾留白根据最后一轮正文的实际高度、输入区高度和容器留白计算，不再累加滚动高度差，也不借用原生折叠 spacer。正文增长时等量消耗末尾留白，防止两套补位互相反馈。新增内容、流式文字和原生计时变化在 MutationObserver 微任务中同步处理，不拖到下一动画帧，让原生跟随滚动与留白回收在显示前完成。标题定位沿用原消息节点，不重建 React 子树。

状态和用时各保留最小宽度；尚无用时时也保留空栏，数字使用等宽数字，避免准备、运行、完成及 9 秒到 10 秒切换时挤动标题和复制按钮。滚动容器保留稳定的滚动条槽。移除已经不参与相对定位的零高度定位节点，避免它受到原生兄弟间距规则影响。

无头真实 DSH 验收：859 帧覆盖准备、工具等待、实时用时和完成；504 帧覆盖回看历史期间生成及收起 1628px 高的回复。标题与复制按钮位置、标题及状态栏宽度、生成阶段正文起点、完成后正文起点均无漂移，页面脚本错误为零。完成时由原生折叠过程替换为最终正文，属于内容切换；未将不同正文节点的坐标当成同一节点抖动。另复查 640px 窗口与滚动条出现/消失的列宽，以及首次、连续、回看历史后发送的 24 个可见首帧，发送即置顶仍通过。验收复用现有桌面 Host，未重启用户服务。
