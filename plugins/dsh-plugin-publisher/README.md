# 插件发布管理

适用于 DeepSeek Harness `0.2.2-rc.5`，在左侧栏的「我的插件」中查看开发仓库里的插件、当前 DSH 配置中的安装状态、GitHub 发布历史和各版本下载量。

## 安装

1. 克隆本仓库。打开 DSH 的「插件 → 添加插件」，选择克隆目录中的 `plugins/dsh-plugin-publisher` 绝对路径并启用。
2. 打开左侧栏的「我的插件」。可从这里安装本地开发版，或进入已装插件的原生详情进行管理。

插件默认从自身所在的 Git 工作区读取 `plugins/*/package.json`。从打包文件安装，或管理另一份采用同一目录结构的仓库时，在启动 DSH Host 前将 `DSH_PLUGIN_PUBLISHER_REPO` 设为目标仓库的绝对路径。

## 发布版本

1. 安装支持 `git archive --mtime` 的 Git 和支持 `gh api --slurp` 的 GitHub CLI。在 DSH Host 的运行账号下执行 `gh auth login`，使用对目标公开仓库有发布权限的账号。
2. 更新插件自己 `package.json` 中的版本号。提交该插件的文件，并推送或合入 GitHub 的默认分支。
3. 按仓库首页的「发布前检查」运行 `npm run check:release -- <插件目录名>`。检查会安装并启用最终的 `.tgz`，通过后保留待发布的安装包和本地检查记录。
4. 在「我的插件」选择「发布版本」，填写更新说明后确认。DSH 核对本地提交和默认分支中的插件目录是否一致，然后上传通过检查的 `.tgz`，校验附件后公开 GitHub Release。
5. 在「查看发布记录」复制安装链接。其他用户可把链接粘贴到 DSH 的「添加插件」，也可以下载并选择本地 `.tgz`。

每个插件版本的发布标签为 `<目录名>@<版本>`。如果上传中断，可重新提交同一版本继续自己的草稿。若草稿或标签冲突，先到 GitHub 检查已有记录。

## 下载数据

每个版本显示 GitHub Release 附件的累计下载次数。安装链接走同一个附件地址，因此通过该链接取得插件包的请求也可能计入下载量。这个数据包含重复下载，无法判断安装是否成功，也无法统计从 Git、源码 ZIP 或本地路径安装的次数。GitHub API 不可用时，面板显示数据暂不可用。登录 GitHub CLI 后，读取发布记录可使用认证额度。
